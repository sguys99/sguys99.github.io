# 7.1 반응형 후속 시안 (4건)

7.1 반응형 검수에서 나온 남은 모양 문제 4건. 실제 빌드 화면에 `variants.css`를 얹어 `shots.mjs`로 찍었다 (g5/cv-button과 같은 방식).

- 보기: `index.html` (안별 나란히, en·ko 라이트 + en 다크). 전체 PNG는 `shots/` (`제안-안-언어-테마-폭.png`, `cur` = 현재 빌드)
- 다시 찍기: `npm run build && npx astro preview --port 4410` → `node docs/design-drafts/g7/responsive/shots.mjs http://localhost:4410`
- 모든 값은 토큰만 사용. CV는 `screen` 미디어 쿼리 안에서만 바꾸므로 인쇄·PDF 조판은 그대로.

## 1. CV 화면 ≤720px (360/390px)

지금: 기간 열 28mm(약 106px)가 남아 360px에서 본문이 약 200px로 좁다.

| 안 | 의도 | 장점 | 단점 |
|---|---|---|---|
| 현재 | 기간 열 + 본문 2열 | 인쇄와 같은 구조 | 본문이 좁아 줄 수가 많고 길이가 약 1.5배 |
| **A** | 1열, 기간을 제목 위 작은 라벨로 | 본문 폭 최대, 홈 원장·모바일 관례와 같은 읽기 순서 | 기간이 세로로 흩어져 훑어보기는 약간 약함 |
| B | 기간을 제목 줄 오른쪽 끝에 띄움(float) | 이력서다운 모양, 본문 폭 최대 | 긴 제목이 기간 옆에서 일찍 꺾여 줄이 고르지 않음 (예: "PwC Consulting, Digital / & AI") |
| C | 2열 유지, 기간 열 15mm로 줄이고 두 줄로 (`2026 –` / `Present`) | 인쇄와 같은 골격 | 본문은 여전히 좁은 편(약 250px), 기간이 두 줄로 쪼개짐 |

**추천: A.** 360px에서 가장 읽기 쉽고 규칙이 단순하다 (행 1열 한 줄).

## 2. 케이스 기록표 861–1100px (사이드바 280px)

지금: 키 열 96px 때문에 값 열이 약 107px. 기간이 두 줄 + 배지 한 줄, 스택은 이름 하나에 한 줄씩 9줄.

| 안 | 의도 | 장점 | 단점 |
|---|---|---|---|
| 현재 | 키 96px + 값 | 넓은 폭(>1100)과 같은 모양 | 값이 좁아 기간·스택이 길게 늘어짐 |
| **A** | 이 구간에서 모든 행을 키 위·값 아래로 | 값 폭 약 232px, 기간 한 줄·스택 4줄. 행마다 모양이 같아 정돈됨 | 짧은 행(Lead, GenON)도 두 줄이 됨. 다만 스택이 줄어 전체 높이는 오히려 짧음 |
| B | 스택 행만 키 위·값 아래 | 바뀌는 곳이 가장 적음 | 기간은 여전히 두 줄 + 배지, 행끼리 모양이 섞임 |
| C | B + 스택을 칩(도메인 태그 모양, 5.7)으로 | 스택이 한눈에 낱개로 보임 | 사이드바에 칩이 생겨 다른 폭(>1100, ≤860)과 모양이 달라짐. 장식이 늘어 Quiet Dossier 톤과 거리 |

**추천: A.** 좁은 구간 하나에만 걸리는 규칙이고, 기간·스택 둘 다 풀린다.

## 3. 모바일 이전·다음 (≤860px, 케이스 끝)

지금: 라벨 `min-width: 64px`보다 "← Previous"가 넓어 영문에서 두 제목의 시작 x가 다르다 (국문은 맞음).

| 안 | 의도 | 장점 | 단점 |
|---|---|---|---|
| 현재 | 라벨 + 제목 한 줄 | — | 영문에서 제목 시작이 어긋남 |
| A | 라벨 열을 두 링크가 공유 (`subgrid`, 긴 라벨 폭에 맞춤) | 모양은 그대로, 언어와 무관하게 제목이 맞음. 최소 변경 | 라벨이 작은 회색이라 탭 대상으로는 여전히 약함 |
| **B** | 라벨을 제목 위 작은 대문자로, 제목은 본문색·한 단계 크게 | 제목 폭 최대, 탭 대상이 분명하고 글 끝 마무리로 잘 읽힘 | 높이가 약 1.5배 |
| C | 단어 없이 화살표만 (단어는 화면 낭독기용으로 남김) | 가장 간결, 정렬 문제 자체가 없음 | ←/→만으로 이전·다음 뜻이 덜 분명함 |

**추천: B.** 모바일에서는 이 두 줄이 글 끝의 다음 행동이라 조금 크게 보여도 된다. 높이 부담이 싫으면 A.
참고: 넓은 폭 사이드바의 이전·다음(5.24.5)도 영문에서 같은 어긋남이 있다 (rec 스크린샷 맨 아래). A의 `subgrid` 규칙은 미디어 쿼리 없이 두 곳 모두에 쓸 수 있다.

## 4. "In progress / 진행 중" 배지 줄바꿈 들여쓰기

지금: `.badge.live`의 `margin-left: --sp-2`가 줄이 바뀐 뒤에도 남아 다음 줄에서 8px 들여 써진다 (기록표 기간 행, 861–1100px 영문).

| 안 | 의도 | 장점 | 단점 |
|---|---|---|---|
| **A** | 배지 여백을 없애고, 간격을 앞쪽에 둠 (Outcome 제목 `.hd`는 `column-gap`, 기간 행은 날짜 `.num`의 `margin-right`) | 줄이 바뀌면 배지가 왼쪽 끝에 맞음. 한 줄일 때 모양은 그대로 (국문 한 줄 유지) | 규칙이 두 곳으로 나뉨 |
| B | 그대로 | 변경 없음 | 줄바꿈 때 8px 어긋남 |

**추천: A.** 사실상 정렬 버그 수정에 가깝다. 2번에서 A를 고르면 1000px에서 기간 행이 넓어져도 영문은 배지가 여전히 다음 줄로 가므로 A가 같이 필요하다.
