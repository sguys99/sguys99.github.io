① 과제 선별 깔때기

자리: Approach 목록 아래 (approach). 163건에서 로드맵 26건, PoC 3건까지 거른 과정

A

단계 원장 막대

의도
다섯 단계를 행으로 쌓고, 막대 길이를 건수에 비례시켜 왼쪽 정렬 깔때기 실루엣을 만든다. 행마다 날짜와 거른 기준을 한 줄씩.
장점
수치가 정직하게 비례. 기준·날짜를 함께 읽혀 설명력이 높고 구현이 단순.
단점
163 → 3의 낙차가 커서 아래 막대가 짧다. 그림 자체의 인상은 가장 차분함.
B

단위 격자 (작은 그림 5개)

의도
과제 하나 = 네모 하나. 163칸 격자에서 24칸이 남고, 유형으로 나뉘고, PoC 3건으로 끝난다.
장점
“많이 걸렀다”가 한눈에 보이고 가장 기억에 남음. ③ 로드맵 범례와 같은 네모 모양으로 이어짐.
단점
3–5단은 네모를 키워 그림 간 크기가 다름. 2단의 남은 칸 위치는 임의(점수 아님).
C

2개월 타임라인 흐름

의도
3.7–5.10 날짜 축 위로 과제 흐름의 두께(=건수)가 바뀐다. 2차 수집에서 부풀고, 선별에서 좁아지고, 분류에서 세 갈래로.
장점
2개월간 수집 → 평가 → 분류 → 로드맵의 진행이 보여 컨설팅 방법론이 드러남.
단점
가장 복잡. PoC 3건은 나오지 않음. 단계 이름이 짧아짐.

② 분류 매트릭스

자리: Approach, ① 아래. 상위 24건을 사업 영향도 × 기술 성숙도로 나눠 추진 방식을 정함 (자료 6·7장 배치 그대로: 가로 영향도, 세로 성숙도)

A

컨설팅 2×2

의도
축 화살표와 네 칸. 칸마다 추진 방식 이름, 건수, 2줄 설명, 예시 과제. PoC 칸 하나만 포인트 색.
장점
컨설팅 결과물의 인상이 가장 강함. 각 영역의 추진 방식이 문장으로 남음.
단점
글이 많아 그림이 큼(372 높이).
B

표형 2×2 + 단위 네모

의도
행·열 머리를 단 표 모양 매트릭스. 칸마다 과제 수만큼 네모, 수행팀 PoC 2건은 포인트 색.
장점
건수 비교가 즉시 보이고, ③ 로드맵과 같은 범례로 이어짐. 축 화살표 없이 깔끔.
단점
예시 과제명과 영역 설명이 짧아짐.
C

①+② 합본 파이프라인

의도
163 → 24 → 매트릭스 → 26(+2)를 한 장에. ①을 따로 넣지 않는 안.
장점
그림 수가 줄어 Approach가 가벼움. 선별과 분류의 관계가 한 줄로 이어짐.
단점
매트릭스 칸이 작아 추진 방식 설명이 빠짐. PoC 3건 단계 없음.

③ 3개년 로드맵

자리: 새 섹션 Roadmap / 로드맵 (Outcome 앞) 또는 Outcome 소제목. 2024-05 최종본 26건, 과제명은 일반 명칭

A

추진 방향별 Gantt (26건 전부)

의도
레인 = 추진 방향 4개, 가로 = 2024–2026 반기. 막대 모양으로 추진 방식, 수행팀 PoC 2건만 포인트 색.
장점
실제 로드맵 결과물에 가장 가까워 규모와 밀도가 그대로 보임.
단점
복잡도 예산(12개) 초과, 막대 글자 11px. 좁은 화면은 가로 스크롤.
B

착수 시점 점도표

의도
레인 × 반기 칸에 그 반기에 착수하는 과제를 네모로. 이름은 수행팀 PoC만, 아래에 반기별 착수 건수.
장점
가볍고 한눈에 리듬(2024 하반기에 착수 집중)이 보임.
단점
기간과 과제명이 빠져 “무엇을”이 약함.
C

추진 방식별 Gantt + 배치 원칙

의도
레인을 추진 방식(솔루션·PoC·데이터 기반·개발 준비)으로 바꾸고 배치 원칙을 메모로.
장점
“솔루션 먼저, 데이터 플랫폼 후 개발 준비” 같은 로드맵 설계 논리가 드러나 컨설팅 역량을 강조.
단점
추진 방향(비전 3축)이 빠짐. 세로로 가장 김.
