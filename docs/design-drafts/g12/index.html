05 Architecture 섹션 (SCM과 같은 자리)

A

학습 | 엔진 나란히

노드 13 · 720×476
의도
오프라인 학습 프로그램과 MixPlanner 엔진을 같은 무게로 나란히 두고, 데이터 원천을 바닥에 깔았다. 엔진 안에 조합 탐색 루프를 한 겹 더 넣었다.
장점
두 산출물(모델 학습 프로그램, 조합 엔진)이 함께 보인다. 모델이 엔진에 탑재되는 지점이 가운데에서 바로 읽힌다.
단점
노드 13개로 밀도가 높다. 계획 화면과 엔진의 왕복을 양쪽 화살표 하나로 줄였다.
B

엔진 중심 · 학습은 아래 띠

노드 13 · 720×452
의도
읽는 순서를 데이터 → 엔진 → 담당자로 두고, 학습 프로그램은 엔진 아래 얇은 띠로 내렸다. 모델은 아래에서 위로 탑재된다.
장점
서비스가 실제로 도는 길이 주인공이다. 담당자의 설정 입력과 결과 검토가 오른쪽 끝에서 닫힌다.
단점
학습 쪽 상세(파이프라인 단계)는 "파이프라인" 한 칸으로 줄었다. ④를 같이 쓰면 보완된다.
C

배치 관점 · PoC → 파일럿

노드 7 · 720×336
의도
슬라이드 41·43처럼 어디에서 무엇이 도는지를 보여준다. 왼쪽은 PoC(오프라인), 가운데는 파일럿 서버, 오른쪽은 기존 시스템이다.
장점
노드 7개로 가장 가볍다. 파일럿까지 갔다는 성과와 바로 이어진다.
단점
엔진 내부 동작은 부제 한 줄뿐이다. 흐름은 ② Service flow가 맡아야 한다.

② Service flow · 조합 산출 흐름

06 Service flow 섹션

A

스윔레인 · 4단계 열

노드 11 · 720×420
의도
원본 슬라이드 33을 따랐다. 담당자 줄과 자동화 줄, 4단계 열(신규 실행 → 데이터 추출 → 재고 범위 → 조합 추천)로 나눴다.
장점
누가 무엇을 하는지와 단계 순서가 함께 보인다. SCM 흐름도와 문법(열 영역, 가운데 이름)이 같다.
단점
"기준 미달 → 차순위 재고로 조정" 루프가 조합 검색 ⇄ 점도 예측 왕복으로만 표현된다.
B

세로 척추 · 함수 순서

노드 11 · 720×656
의도
MixPlanner 함수가 실행되는 순서대로 위에서 아래로 내려간다. 미달 시 조정 루프와 후보 소진 시 설정 변경 경로를 따로 그렸다.
장점
알고리즘 동작이 가장 정확하다 (기본 조합 → 예측 → 판정 → 조정 → 재예측, 후보가 없으면 설정 변경 안내).
단점
세로로 길다(656). 모바일에서는 스크롤이 길어진다.
C

루프 중심

노드 9 · 720×452
의도
위 한 줄은 준비 단계(설정 → 초기화 → 재고 선별), 아래 큰 영역은 조합 탐색 루프다. 루프 영역 이름에 "건당 약 10초"를 넣었다.
장점
이 프로젝트의 핵심인 탐색 루프가 가장 크게 보인다. 결과가 담당자에게 돌아가는 길이 닫혀 있다.
단점
데이터 원천(DB)은 초기화 부제로만 남는다. ①과 함께 써야 원천이 보인다.

02 Problem 아래 (새 자리, 컴포넌트에 슬롯 추가 필요)

A

위아래 두 줄

노드 12 · 720×416
의도
슬라이드 9처럼 현행 줄과 개선 줄을 위아래로 맞췄다. 줄 이름에 건당 소요 시간을 넣었다.
장점
같은 열끼리 비교된다. 점도맵이 ML 모델로 바뀌는 자리가 정확히 겹친다.
단점
두 줄의 단계 수가 같아 보이게 맞추느라 현행 단계를 일부 묶었다.
B

좌우 두 기둥 + 지표

노드 14 · 720×624
의도
현행과 개선을 왼쪽·오른쪽 기둥으로 세우고, 바닥에 건당 시간과 점도 오차를 큰 숫자로 뒀다.
장점
결과 숫자(20분 → 10초, 6.5% → 3.4%)가 가장 강하게 남는다.
단점
세로로 길다(624). 숫자가 Outcome 섹션과 겹친다.
C

바뀐 단계만

노드 6 · 720×288
의도
입력과 확정은 공통이고, 바뀐 두 단계(조합 구성, 점도 확인)만 현행(흐린 점선)과 개선으로 나눴다.
장점
가장 짧고(288) 메시지가 하나다. 문단 사이에 넣어도 부담이 없다.
단점
수작업 시행착오 루프가 글자로만 남는다.

04 Approach 아래 (새 자리)

A

ㄹ자 한 줄 흐름

노드 8 · 720×236
의도
원시 데이터 → 데이터셋 → 두 파이프라인 → 학습·평가 → 목표(MAPE 5% 이내) 판정 → 탑재를 한 번에 그렸다. 미달이면 파이프라인으로 돌아간다.
장점
짧고(236) 목표 기준과 재학습 경로가 보인다.
단점
파이프라인 안의 단계는 부제 한 줄로만 보인다.
B

파이프라인 펼침

노드 11 · 720×300
의도
데이터 파이프라인 4단계와 모델 파이프라인 3단계를 영역 안에 펼쳤다 (scikit-learn Pipeline 구조).
장점
구현 깊이(전처리 설계)가 드러난다.
단점
케이스 스터디 독자에게는 상세할 수 있다. 판정·재학습 경로는 뺐다.
