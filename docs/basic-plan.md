|---|---|---|

### 1.2 성공 기준

- 이력이 바뀌면 데이터 파일 한 곳만 고쳐서 영문·국문 사이트와 PDF CV가 함께 갱신된다.

## 2. 참고 사이트 분석 (uye01.github.io)

참고 사이트를 직접 열어 구조와 스타일 값을 확인한 결과입니다.

### 2.1 구조
- **단일 페이지**. 상단 고정 내비게이션(About / Education / Publications / Experience / Projects / Activities)이 앵커 스크롤과 현재 위치 밑줄 표시를 담당.
- **2단 레이아웃**: 왼쪽 고정 사이드바(약 250px: 사진, 이름, 소속, 연락처 링크) + 오른쪽 본문(약 660px) 카드 스트림.
- 본문은 섹션 제목(작은 사각 불릿 + 제목) 아래에 흰색 카드가 쌓이는 구조.
- About 카드 안에 **PAST / NOW / NEXT 칩**으로 연구 궤적을 한 줄로 요약.
- 항목 행 패턴: 28px 기관 로고 + 제목 + 부제 + 오른쪽 정렬된 모노스페이스 날짜.
- 논문 항목에 Paper / Code 배지 링크. 푸터에 최종 수정일과 방문자 수.

### 2.2 스타일 값
| 요소 | 값 |
|---|---|
| 배경 / 카드 | 따뜻한 오프화이트 `#FBFBF9` / 흰색 `#FFFFFF`, 1px 테두리 `#E8E8E3`, 모서리 12px, 그림자 없음 |
| 텍스트 | 본문 `#1E2128`, 보조 `#5F6672`, 흐린 `#969CA8` |
| 포인트 색 | 인디고 `#2C46C7` + 시안 `#3FBBD8` (이름에 그라디언트, 배경에 옅은 글로우) |
| 서체 | 제목 Space Grotesk 600 / 본문 Public Sans 15px / 날짜·태그 IBM Plex Mono |
| 다크모드 | `data-theme` 토글, 배경 `#0C0E14`, 카드 `#161A24` |
| 기타 | 스크롤 등장 애니메이션, 미세한 그레인/도트 배경, GoatCounter 방문 집계 |
| 구현 | 프레임워크 없는 단일 HTML + 인라인 CSS로 보임 |

### 2.3 계승할 것과 새로 설계할 것 [확정]
답변에서 **고정 사이드바 구조, 카드형 섹션 구성, 서체와 타이포 위계** 세 가지를 선택하셨습니다. 색감과 여백은 선택하지 않으셨으므로 자유롭게 재설계합니다.

| 구분 | 방침 |
|---|---|
| 계승 | 사이드바 + 본문 2단 골격, 카드 단위 섹션, 제목/본문/메타 서체의 역할 분리, 일관된 항목 행 문법 |
| 재설계 | 색 체계와 여백 리듬, 카드 내부 구성, 사이드바 내용, 모션, 다크모드, 모바일 전환 방식 |
| 신규 | 경력 궤적 표현, 대표작/아카이브 이원화, 필터, 케이스 스터디, 언어 전환, 인쇄용 CV |

### 2.4 그대로 가져올 수 없는 이유: 분량
참고 사이트는 **대학원생의 1페이지 분량** 콘텐츠에 맞춘 구조입니다.

| 구분 | 참고 사이트 | 본 프로젝트 (이력서 기준) |
|---|---|---|
| 경력 | 3곳 | 6곳 (2008~현재) |
| 프로젝트 | 4건 | 18건 |
| 논문/특허 | 논문 4편 | 논문 3편, 특허 15건(등록 7, 출원 8), 프로그램 등록 10건, 보고서 50여 편 |
| 기타 | 활동 2건 | 강의·자문 8건, 저서 2권, 수상 4건 |

같은 카드 스트림에 전부 넣으면 스크롤이 매우 길어지고 핵심이 묻힙니다. 핵심 설계 과제는 **"많은 실적을 minimal하게 보이게 하는 밀도 조절"** 입니다. 또 하나의 과제는 **영문과 국문에서 모두 균형 잡힌 타이포그래피**입니다(영문 서체와 국문 서체의 굵기·자간·행간이 다르기 때문).

## 6. 디자인 프로세스

### 6.1 원칙: 모든 디자인 결정은 시안 2~3개 → 선택 → 기록
1. 결정 지점(Gate)마다 **실제 콘텐츠를 넣은 HTML 시안 2~3개**를 만듭니다.
2. 시안은 데스크톱/모바일, 라이트/다크, 영문/국문을 함께 보여주고, 각 시안의 의도와 장단점을 1~2줄로 붙입니다.
3. 선택(또는 "A의 레이아웃 + C의 타이포" 같은 조합)을 받으면 구현에 반영합니다.
4. 선택 결과와 이유를 `DESIGN.md`의 Decision Log에 기록합니다. 선택되지 않은 시안은 `docs/design-drafts/`에 보관합니다.

### 6.2 디자인 결정 지점 (Gate)
| Gate | 결정 대상 | 시안 내용 |
|---|---|---|
| G1 | 전체 콘셉트 | 사이드바 + 카드 골격 위에서 성격이 다른 홈 시안 3개 (아래 6.3) |
| G2 | 타이포·컬러 토큰 | 영문·국문 서체 조합, 포인트 색, 여백 리듬 2~3개 |
| G3 | 사이드바·히어로·경력 궤적 | 사이드바 구성, 문구 후보(3.2), 궤적 시각화 방식 |
| G4 | 프로젝트 표현 | 대표작 카드 형태, 전체 목록과 필터, 케이스 스터디 레이아웃 |
| G5 | 고밀도 목록 | 특허·논문·보고서의 접힘/표/필터 방식 |
| G6 | 모션·다크모드·세부 인터랙션 | 등장 효과 강도, 호버, 테마·언어 전환 |

### 6.3 G1에서 제시할 콘셉트 방향 (예고)
세 시안 모두 선택하신 **고정 사이드바 + 카드 + 타이포 위계**를 공유하고, 성격과 밀도에서 차이를 둡니다.

| 시안 | 방향 | 특징 | 인상 |
|---|---|---|---|
| A. Quiet Dossier | 참고 사이트에 가장 가까운 정제형 | 무채색 바탕, 얇은 선의 카드, 포인트 1색, 차분한 산세리프 | 단정하고 중립적 |
| B. Editorial Dossier | 타이포를 크게 쓰는 편집형 | 큰 섹션 제목과 강한 대비, 카드 테두리를 줄이고 여백으로 구분, 대표작은 넓은 카드 | 잡지 같은 세련됨 |
| C. Blueprint Dossier | 엔지니어링 문서형 | 모노스페이스 메타 정보, 번호가 붙은 섹션, 경력 궤적을 사이드바의 세로 축으로 시각화 | 기술적이고 구조적 |

### 6.4 디자인 원칙 (DESIGN.md의 출발점)
1. **Content first**: 장식보다 문장과 위계. 장식 요소는 정보를 전달할 때만 사용.
2. **One accent**: 무채색 바탕에 포인트 색 1개(보조 1개까지).
3. **Line over shadow**: 그림자·그라디언트 최소화, 얇은 선과 여백으로 구분.
4. **Consistent row grammar**: 모든 목록 항목이 같은 문법(제목 / 부제 / 메타 / 날짜).
5. **Progressive disclosure**: 기본은 요약, 원하면 펼침.
6. **Bilingual parity**: 영문과 국문이 같은 레이아웃에서 같은 완성도로 보이게 서체·행간을 언어별로 조정.
7. **Quiet motion**: 150~250ms의 짧은 전환만, `prefers-reduced-motion` 준수.
8. **Light/dark parity**: 두 테마 모두 1급으로 설계.
9. **Print-ready**: `/cv` 는 A4 인쇄 기준으로 따로 조판.

### 6.5 DESIGN.md 목차 (예정)
`1. Brand & Tone` → `2. Principles` → `3. Tokens (color / type / spacing / radius / motion)` → `4. Layout & Breakpoints` → `5. Components` → `6. Page Templates` → `7. Bilingual Typography` → `8. Dark Mode` → `9. Accessibility` → `10. Print` → `11. Decision Log (Gate별 시안과 선택)`
